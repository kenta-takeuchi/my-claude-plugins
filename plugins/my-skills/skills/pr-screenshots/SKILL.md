# pr-screenshots

実装した画面のキャプチャを Playwright MCP で取得し、PR 本文を最新の変更内容に書き直して、キャプチャの貼り付け位置をプレースホルダーで示す Skill。引数 `$ARGUMENTS` は任意。

## 引数

- **PR番号（任意）**：例 `406` / `#406`。省略時はカレントブランチの PR を `gh pr view --json number` で特定する。
- **対象URL・画面の指示（任意）**：キャプチャすべきパスや状態（タブ・フィルタ等）の指定。例「/orders の全タブ」「詳細画面も」。省略時は PR の差分から対象画面を推測する。

## 前提

- ローカル dev サーバーが起動していること。`lsof -iTCP -sTCP:LISTEN -P | grep -E "5173|3000"` 等で確認し、**起動していなければユーザーに起動を依頼して止まる**（dev サーバーは `kp run` を要するためユーザー側で起動するのが基本。`! pnpm --filter '@mr-texpress/order' dev` を案内する）。
- `gh` 認証済みであること。

## 手順

### 1. 対象の特定

1. PR 番号を引数またはカレントブランチから特定し、`gh pr view <番号> --json title,body,files` で現在の本文と変更ファイルを取得する。
2. キャプチャ対象の画面（ルート）を決める。引数の指示があれば最優先。なければ PR の差分（`app/routes/` 配下の追加・変更）から対象パスを推測する。
3. 一覧画面なら状態タブ（全件/未承認/誤発注 等）やフィルタ適用後など、**UI の分岐が分かる代表的な状態を 2〜4 枚**選ぶ。空状態が意味を持つ画面（0件表示の出し分け等）は空状態も撮る。

### 2. キャプチャ取得（Playwright MCP）

1. `mcp__playwright__browser_navigate` で `http://localhost:<port><path>` を開く。
2. `mcp__playwright__browser_take_screenshot` で PNG を保存する。**ファイル名は `pr<PR番号>-<画面>-<状態>.png`** 形式（例 `pr406-orders-all.png`）。リポジトリルートに保存される。
3. 各キャプチャを Read で目視確認し、意図した状態（タブのアクティブ表示・件数・空表示など）が写っているか検証する。違っていれば撮り直す。
4. 認証リダイレクトされた場合はユーザーにブラウザでのログインを依頼して止まる。

### 3. PR本文の更新

1. 既存の本文をベースに、**ブランチの最新コミットまでの変更内容をすべて反映**して書き直す（後続コミットで増えた機能・削除した要素・テスト件数の更新漏れに注意。`git log origin/main..HEAD --oneline` で差分コミットを確認する）。
2. 「## スクリーンショット」セクションを設け、キャプチャごとに見出し＋**HTML コメントのプレースホルダー**を置く：

   ```markdown
   ## スクリーンショット

   ### 全件タブ

   <!-- ここに pr406-orders-all.png を貼り付け -->

   ### 未承認タブ（0 件時の空表示）

   <!-- ここに pr406-orders-unapproved.png を貼り付け -->
   ```

   すでにスクリーンショットセクションがあり画像が貼られている場合は、**貼付済み画像の URL は壊さず**、追加・変更分のプレースホルダーだけ足す。
3. 本文は一時ファイルに書き出し `gh pr edit <番号> --body-file <一時ファイル>` で更新する（PR本文は日本語。既存の `Closes #<Issue番号>` と `🤖 Generated with [Claude Code](https://claude.com/claude-code)` フッターを維持する）。

### 4. 報告

最後に以下を簡潔に報告する：

- 保存したキャプチャのファイル名一覧と保存場所（リポジトリルート）
- PR 本文の主な更新点
- **画像は `gh` CLI からアップロードできないため、PR 編集画面で各プレースホルダー位置に PNG をドラッグ&ドロップするようユーザーに案内する**
- キャプチャ PNG は git 管理外なので、貼り付け後に削除してよいことを添える

## 注意

- キャプチャは撮りすぎない。UI の分岐・主要な状態が伝わる最小限の枚数にする。
- 本文を書き直すときに、レビューで指摘・修正された内容（受け入れ条件の文言など）を古い記述のまま残さない。
- dev サーバーのポートはプロジェクトにより異なる（vite なら 5173 が既定）。決め打ちせず LISTEN 中のポートを確認する。
